# 点検の方法と道具

(2026-11-13 調べ。対象: `UIUXスキル表.md` の ◎ 104 項目。スキル「/uiux 点検 <サイト>」の設計の元にする)

## 3 行の要点
1. ◎ 104 項目は **自動 41 / 半自動 41 / 人 22** に分けられる。自動の大半は、手元の Chrome を CDP で動かし、ページの中で JS を実行して測る(幅 320/375px の再現、タップ領域、`<img>` の属性、見出し、フォーム、CSS の中身)。ここに axe-core(アクセシビリティ)と Lighthouse(速さ・SEO)を足せば、追加で入れる物は npm パッケージ 2 つで済む [1][3][5]。
2. 道具で分かるのは「規則に合っているか」まで。「何の店か 10 秒で分かるか」「予約まで行けるか」は、**ヒューリスティック評価(3〜5 人が別々に見て、重大度 0〜4 を付けて平均)** と **5 人のユーザビリティテスト(1 人ずつ・思考発話・黙って見る)** でしか分からない [8][9][10][11]。
3. 報告は「重大度・場所(セレクタ+スクショ)・何が起きているか・直し方・スキル表 #」の 1 行 1 問題の表にし、**重大度 4・3 から直す**。自動の結果は「人が確かめるまで仮」とする(axe の `incomplete` や、文字が画像の上にあるときのコントラストは誤判定が出る)[5]。

### WCAG のコントラストの式 [3]
```
各色(R,G,B)を 0〜1 にする: c = 値 / 255
直線化: c ≤ 0.04045 なら c/12.92、それ以外は ((c+0.055)/1.055)^2.4
相対輝度 L = 0.2126·R + 0.7152·G + 0.0722·B
コントラスト比 = (明るい方の L + 0.05) / (暗い方の L + 0.05)   … 1〜21
合格: 本文 4.5 以上 / 大きい文字(24px 以上、太字は 18.5px 以上)3 以上 / ボタンの枠・アイコン 3 以上
四捨五入しない(4.499 は不合格)
```
(しきい値 0.04045 は 2021-05 に旧値 0.03928 から直ったもの。結果はほぼ変わらない [3])

## スキル表 ◎ の点検方法
自動 = スクリプトが合否まで出す / 半自動 = スクリプトが数字・候補・スクショを出し、人が決める / 人 = 人が見る・使う。
「375」「320」は CDP の `Emulation.setDeviceMetricsOverride` で幅を指定した状態(thumb.py の iframe と違い、ウィンドウの最小幅の制約を受けない見込み。未確認)。

## ヒューリスティック評価の手順
NN/g のやり方 [8][9][10]:
1. **準備**: 物差しを決める(ニールセンの 10 原則+ノレンのスキル表 ◎)。範囲を絞る(例:「スマホで、初めての人が料金を見て予約する」の 1 本)。記録の形を決める(下の表)。
2. **1 人ずつ別々に見る**(1〜2 時間まで)。1 周目は全体をつかみ、2 周目でタスクをなぞりながら原則に反する所を書く。直し方の案も書く。
3. **持ち寄ってまとめる**: 同じ問題をまとめ、意見が分かれた所を話し、ユーザーと店にとっての大事さで順位を付け、直す物と次に試す物を決める。
- **人数**: 3〜5 人が別々に [9]。1 人の評価では見落としが多い。ノレンは代表+外の人 2 人(知人のデザイナー・家族)で 3 人を目安にする(この人数の当てはめはノレンの判断)。
- **重大度 0〜4**(頻度・越えにくさ・何度も困るか、の 3 つを合わせて付ける。1 人の付けた値は当てにならないので 3 人の平均を使う)[8]:
  - 0 = 問題ではない / 1 = 見た目だけ。時間があれば直す / 2 = 小さい問題。優先度低 / 3 = 大きい問題。優先して直す / 4 = 致命的。公開前に必ず直す
- **ニールセンの 10 原則** [10] と店舗サイトでの見どころ:
  1. システムの状態を見せる — 送信中・送信済み、今どこのページか
  2. 実世界に合わせる — 「メニュー・料金」「アクセス・駐車場」のお客さんの言葉
  3. ユーザーの自由 — 戻れる、閉じられる、電話をやめられる
  4. 一貫性と標準 — ロゴ左上・予約ボタンが 1 種類
  5. エラーを防ぐ — 日付の入力、電話番号の形式
  6. 覚えさせず見せる — 料金がメニューの横、営業時間がどこでも見える
  7. 柔軟さと効率 — 電話・LINE・予約の選べる導線
  8. 美しく最小限 — 最初の画面に詰め込まない
  9. エラーの認識・診断・回復 — どう直すかを欄のそばに
  10. ヘルプと説明 — よくある質問が予約ボタンの近く

## 5 人テストの進め方(台本・タスク例・記録)
**考え方** [11][17][18]: 5 人で問題の約 85% が見つかる(1 人で約 31%。見つかる割合 = 1 −(1 − 0.31)^人数)。15 人を 1 回より、5 人 × 3 回(直してまた試す)の方がよい。客層が 2 つに分かれるなら 1 つにつき 3〜4 人。**1 人ずつ**行い、複数人を同時に集めない [18]。

**準備**
- 参加者: 客層に近い人(例: 整体なら 40〜60 代、居酒屋なら 20〜40 代の会社員)。社内・家族は 1 人まで。
- 機材: 参加者のスマホ(普段の物が一番よい)、画面録画(iPhone の画面収録)か、横から別のスマホで手元を撮る。オンラインなら画面共有。
- 時間: 1 人 30〜45 分。
- 謝礼の目安(国内): 一般の人で 1 時間前後 **3,000〜8,000 円、5,000 円前後が中心**。会場に来てもらう形は高め(8,000〜20,000 円の例)。いずれも事業者・個人の記事の目安で、公的な統計ではない [19][20]。知人に頼むならギフト券 1,000〜3,000 円や食事でもよい(ノレンの判断)。

**店舗サイト向けのタスク例**(実際の場面に近い言い方にし、ボタンの名前を言わない [21])
