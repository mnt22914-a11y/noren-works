# スマホとインタラクション

調査日: 2026-11-12 / 対象: 小さな店舗(飲食・美容・整体・ジムなど)のホームページ
根拠の強さ: A=規格・一次研究 / B=業界の調査・大手のデザインシステム / C=ブログ・慣習・二次情報

## 3 行の要点

1. **押す場所は大きく・離して・親指の届く所に**。最低 24×24px(WCAG AA)、目標は 44〜48px 角+間隔 8px。画面の中央は押しやすく、隅は押しにくい(隅は約 12mm 必要)。
2. **隠さない・邪魔しない**。メニューを隠すと見つけてもらえる率が 20% 以上落ちる。最初からポップアップを出さない。自動で回るスライダーを使わない。勝手にスクロールを奪う演出(スクロールジャック)は害の方が大きい。
3. **フォームは短く・ラベルは上に・正しいキーボードを出す**。項目は必要最小限、プレースホルダーをラベル代わりにしない、`type` と `autocomplete` を付ける、エラーは欄を離れたときに欄のすぐそばに出す。

## 補足(大事なものだけ数行ずつ)

**タップ領域(1〜6)**
WCAG 2.2 の AA は 24px と低めですが、これは「最低ライン」です。iOS 44pt・Android 48dp に合わせて、ボタンは高さ 48px 前後を基本にすると両方を満たせます。見た目のアイコンが小さくても、`padding` で押せる範囲を広げれば OK。文中のリンク(文章中の単語リンク)は WCAG の例外ですが、「電話」「予約」などの主要ボタンは必ず大きくします。

**親指ゾーン(6〜10)**
よく見る「画面下の中央が緑、上の隅が赤」の扇形図は、Hoober 自身の後の研究で「人は画面の中央を好んで見て押す」「隅は押しにくいので大きく(約 12mm)」に更新されています。下部固定ボタンは「押しやすい」より「いつでも見えている」ことが価値だと考えるのが正確です。

**ナビ(14〜18)**
NN/g の実測では、メニューを隠すとスマホでも使われる率が 57% にとどまり、見せるのと併用すると 86% まで上がります。店舗サイトなら「メニュー」「料金」「予約」「アクセス」程度は画面上に出し、その他(会社概要・採用など)をハンバーガーに入れる形が無難です。

**ファーストビュー(19〜20)**
閲覧時間の 74% は最初の 2 画面。ここで「何の店か」「どこにあるか」「どう予約するか」が分からないと、下まで読まれません。とはいえスクロール自体は自然な行動なので、無理に 1 画面に詰め込む必要はありません。

**フォーム(43〜56)**
予約・問い合わせフォームは「名前・連絡先・希望日時・内容」の 4〜6 項目程度に抑えるのが現実的です(EC でも必要なのは約 8 項目)。電話番号欄には `type="tel" autocomplete="tel"`、メールには `type="email" autocomplete="email"`、郵便番号は `inputmode="numeric" autocomplete="postal-code"`。エラーは欄を離れた時点で欄の直下に赤字+アイコン+文で。

**動き(38〜42)**
迷ったら「150〜300ms、ease-out 系の曲線、`prefers-reduced-motion` で止める」。ファーストビューで文字がふわっと出る演出は、読むのを遅らせるだけなので控えめに。

## 未確認・意見が割れていること

- **Apple HIG の 44pt と間隔の値**: 44×44pt は複数の二次情報で一致するが、Apple の公式ページ本文は今回取得できず直接確認できなかった。「間隔 8pt」という二次情報は**未確認**。
- **Material 3 の数値**: m3.material.io は本文を取得できず、モーション(動き)の時間・曲線の値は二次情報と旧版(M1/M2)ページで確認。`cubic-bezier(0.2, 0, 0, 1)` が「standard」か「emphasized」かは資料で食い違う。
- **Material の下部ナビ 3〜5 項目**: 公式ページの本文は取得できず、検索結果の要約と実装ライブラリの文書で確認。
- **Apple のアニメーション時間の目安(ミリ秒)**: Apple HIG に具体的なミリ秒は見つからなかった(**未確認**)。
- **Hoober の持ち方の比率(49/36/15%)**: 2013 年の観察。本人がその後の研究で指針を更新している。画面の大型化で現在の比率は変わっている可能性がある。
- **「フォームの項目を 11 から 4 に減らしたら CV が 120% 増えた」**などのよく引用される数字: 一次情報を確認できず**未確認**。今回は Baymard の数字だけを採用。
- **フローティングラベル**(入力すると上に小さく移動するラベル): NN/g は「プレースホルダーよりはまし、だが同じ問題を一部抱える」。上置きの普通のラベルが安全。
- **ハンバーガーメニュー**: 「若い世代は慣れているので問題ない」という意見もあるが、NN/g の実測(2016)では隠すと発見率が下がる。店舗サイトの客層は幅広いので見せる方を推奨。
- **画面下の固定ボタン**: 店舗サイトでの効果を示す一次研究は見つからなかった(慣習・C)。iOS Safari の下部ツールバーと重なる、画面を狭くする、という欠点もあり、高さを抑え 1〜3 個に絞るのが無難。
- **横スクロールの写真ギャラリー**: 公的な一次研究は今回見つけられなかった(C)。WCAG 1.4.10 はページ全体の横スクロールを禁じるもので、部品単位の横スクロールは対象外。
- **iOS の 16px 自動ズーム**: 広く知られた挙動だが Apple の公式文書では未確認。
- **日本の全角・半角の扱い**: 「両方受け付けて自動変換」は日本のフォーム設計の慣習(東京都・デジタル庁の資料にもあると思われるが本文を確認できず**未確認**)。
