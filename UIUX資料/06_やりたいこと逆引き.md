# やりたいこと逆引き(動き・機能 → UI/UX と作り方)(2026-11-13)

「こういう動きをさせたい」「こういう機能が欲しい」と言われたときに、何という UI で、どう作り、何に気をつけるかを引く表。
ノレンの決まり(1 ファイル完結、外部は Google Fonts まで、GSAP・Lenis なし、JS が止まっても全部見える、`prefers-reduced-motion` で止める)の中で作れる方法だけを書く。

- **判定**: ◎ 店舗サイトにおすすめ / ○ 条件つきで使う / △ 基本やめる / ✕ やらない
- **作り方**: CSS = CSS だけ / JS = 短い JavaScript / 外部 = 外のサービスにつなぐ
- 決まりの数値と根拠は `../UIUXスキル表.md`(#番号)にある
- **コードは `10_実装レシピ.md`**(同じ名前の見出しで引ける)。業種ごとの注意は `07_業種別.md`

## A. 動き

### A-1. スクロールで現れる・変わる
| やりたいこと | UI の名前 | 判定 | 作り方 | 気をつけること |
|---|---|---|---|---|
| 写真や文字がスクロールでふわっと出る | フェードイン(スクロール表示) | ◎ | JS: IntersectionObserver で `.in` を付ける(今のノレンの型)。CSS: `animation-timeline: view()` | 最初から見える状態で書き、JS が動いたときだけ隠す。移動は 10〜20px・300〜600ms。1 画面に何個も動かさない |
| ヘッダーがスクロールで小さくなる・色が付く | 縮むヘッダー(shrinking header) | ○ | JS: ページ上端に置いた目印を IntersectionObserver で見る。CSS: `animation-timeline: scroll()` | 高さが変わると下の中身がずれる。高さではなく影・背景色を変える |
| 下へスクロールで隠れ、上へ戻すと出るヘッダー | ヘッドルーム型ヘッダー | ○ | JS: スクロールの向きを見てクラスを付け替える | 少しスクロールしてから 300〜400ms で出す(#70)。下の固定バーは隠さない |
| どこまで読んだかのバー | 読み進みバー(progress bar) | △ | CSS: `animation-timeline: scroll()` で横幅を伸ばす | 読み物向け。店舗サイトでは飾りになりがち |
| 背景がゆっくり動き、手前が速く動く | パララックス | △ | CSS: `animation-timeline` で `transform` を動かす | スマホでは酔う・重い。やるならヒーローの 1 枚だけ・PC だけ |
| スクロールすると横に流れる | 横スクロール連動(スクロールジャック) | ✕ | ― | スクロールを奪うと使いにくくなる(#85) |
| 今読んでいる章を目次で光らせる | スクロールスパイ | ○ | JS: 各章を IntersectionObserver で見て `aria-current` を付ける | 1 ページの長いサイトで、目次があるときだけ |

### A-2. 画面を開いたとき
| やりたいこと | UI の名前 | 判定 | 作り方 | 気をつけること |
|---|---|---|---|---|
| ヒーロー写真がゆっくり寄る | ケン・バーンズ効果 | ○ | CSS: `@keyframes` で `scale(1)→scale(1.06)` を 10〜20 秒、1 回だけ | 写真の LCP を遅らせない(写真は最初から表示)。動きを減らす設定では止める |
| 見出しが 1 文字ずつ出る | タイピング・文字アニメ | ✕ | ― | 読めるまで待たされる。ノレンの仕様で「オープニング演出」は禁止 |
| ロゴが出てからサイトが開く | ローディング画面・オープニング | ✕ | ― | 第一印象の 0.05 秒を無駄にする。速さの点数も下がる |
| 背景に動画を流す | 背景動画(ヒーロー動画) | △ | HTML: `<video muted playsinline loop poster="...">` | 重い。一時停止ボタンが必要(5 秒を超えて動くため、#84)。写真 1 枚の方が速く伝わる |
| 写真が自動で切り替わる | スライドショー・カルーセル | ✕ | ― | 押されるのは約 1%。自動送りは読めない(#77) |

### A-3. 触ったとき
| やりたいこと | UI の名前 | 判定 | 作り方 | 気をつけること |
|---|---|---|---|---|
| ボタンを押した感じを出す | 押下フィードバック | ◎ | CSS: `:active{transform:scale(.97)}`、色を少し濃く | 0.1 秒以内に反応(#56)。全部のボタンで同じ動き |
| PC で写真に乗せると少し大きくなる | ホバーズーム | ○ | CSS: `@media (hover:hover){img:hover{transform:scale(1.03)}}` | スマホでは出ない前提にする。ホバーでしか分からない情報を作らない(#87) |
| ページ内リンクでなめらかに移動 | スムーズスクロール | ◎ | CSS: `html{scroll-behavior:smooth}`+各章に `scroll-margin-top`(固定ヘッダーの高さ) | 動きを減らす設定では `auto` に戻す |
| よくある質問がなめらかに開く | アコーディオン | ◎ | HTML: `<details><summary>`。なめらかにするのは CSS の `::details-content` と `interpolate-size`(対応ブラウザだけ) | JS なしで開け閉めできる。なめらかに開くのは Chrome 系だけ(2026-11)。`@supports` で囲み、ほかは一瞬で開くだけにする |
| ページを移るときになめらかに切り替わる | ビュー遷移(View Transitions) | ○ | CSS: `@view-transition{navigation:auto}`(ページをまたぐ遷移は Chrome・Safari が対応。Firefox は未確認) | 対応しないブラウザでは普通に移るだけ。1 ページのサイトでは不要 |
| カーソルについてくる・ボタンが吸い寄る | カーソル追従・マグネット | ✕ | ― | ノレンの仕様で禁止。スマホにはカーソルがない |
| 文字や写真が横に流れ続ける | マーキー(ティッカー) | △ | CSS: `@keyframes` で `translateX` | 一時停止の手段が必要。大事な情報(臨時休業など)を流さない |
| 注目させるために揺らす・点滅させる | アテンション(揺れ・点滅) | ✕ | ― | 広告に見える。1 秒に 3 回を超える点滅は禁止(#84) |
| 数字がカウントアップする | カウントアップ | △ | JS: 見えたら 0 から数える | HTML には最終の数字を書く(JS なしでも正しい数字)。「実績 ○○人」は景表法に注意 |

## B. 機能

### B-1. 連絡・予約
| やりたいこと | UI の名前 | 判定 | 作り方 | 気をつけること |
|---|---|---|---|---|
| 押したら電話がかかる | 電話リンク・固定バー | ◎ | HTML: `<a href="tel:+81312345678">03-1234-5678</a>`、画面下に固定 | 番号を文字でも見せる。受付時間をすぐ横に(#158) |
| LINE で相談してほしい | LINE ボタン | ◎ | 外部: `https://line.me/R/ti/p/%40ID`(友だち追加)/ `line.me/R/oaMessage/%40ID/?本文`(トーク) | 「LINE で相談する」と行き先を書く。返信の目安時間を添える |
| ネットで予約してほしい | 外部の予約システム | ◎ | 外部: 店がもう使っている予約へリンク。新しく選ぶなら「Google で予約」対応(STORES 予約・Square 予約・TableCheck) | 「○○で予約する」と行き先を書く。サイト内に予約の仕組みは作らない(#174・#177)。比較表は `08` |
| 空いている日を見せたい | 空き状況カレンダー | ○ | 外部: 予約システムの空き表示へリンク / 埋め込み | 手で更新するカレンダーは古くなって信頼を落とす |
| 問い合わせフォームが欲しい | フォーム | ○ | 外部: Google フォーム・Formspree・Web3Forms など(GitHub Pages では送信を受けられない。Netlify Forms も不可) | 項目は最小限・項目名は上・利用目的を書く(#89〜100)。CAPTCHA は外部スクリプトなので使わず、見えない罠の欄で受ける(#193) |
| ポップアップでキャンペーンを知らせたい | モーダル・ポップアップ | ✕ | 代わりに「お知らせ帯」 | 開いてすぐのポップアップは読まずに閉じられる(#86) |
| チャットで答えたい | チャットボット | △ | 外部: LINE の自動応答 | 小さな店はよくある質問+LINE で足りる |

| やりたいこと | UI の名前 | 判定 | 作り方 | 気をつけること |
|---|---|---|---|---|
| 臨時休業・お知らせを出したい | お知らせ帯 | ◎ | JS: 同じフォルダの `news.json` を読んで表示 / Google スプレッドシートを CSV で公開して読む(一番手間が少ない。ブラウザから直接読めるかは実機で確認) | JS なしでも見える「いつものお知らせ」を HTML に書いておく。日付を必ず付ける(#114) |
| 今日のおすすめを書き換えたい | 今日の一品 | ○ | 同上(スプレッドシートの 1 マスを店主が書き換える) | 書き換え忘れると古い情報が残る。日付を出す |

| 混み具合を出したい | 混雑状況 | △ | 手で更新 / Google マップの混雑情報へ誘導 | 更新が止まると嘘になる |

## C. 動きの共通ルール(どの動きにも当てはめる)
1. **JS が止まっても全部見える。** 隠すのは「JS が動いたとき」だけ(`.js .fade{opacity:0}`)
2. **動きを減らす設定では止める。** `@media (prefers-reduced-motion: reduce){*{animation:none!important;transition:none!important;scroll-behavior:auto!important}}`
3. **長さは 100〜400ms、距離は小さく。** 出るときは少し長く、消えるときは短く。緩急は「速く始めてゆっくり止まる」
4. **動かすのは `transform` と `opacity` だけ。** `top`・`width`・`height` は動かさない(重い・ずれる)
5. **1 画面で動くのは 1 か所まで。** 動きは「見てほしい物」に使う
6. **大事な情報を動きの中に入れない。** 流れる文字・自動で変わる写真に、休業や値段を入れない
7. **ヒーローの写真は動きを待たせない。** 最初から表示し、動きは後から重ねる
8. **新しい CSS は「なくても困らない」使い方だけ。** 対応しないブラウザでは「動かないだけ」になるように書く

## D. 新しいブラウザの機能(2026-11 時点)
| 機能 | できること | 対応 | 使い方 |
|---|---|---|---|
| スクロール連動アニメ(`animation-timeline`) | JS なしでスクロールに合わせて動かす | Chrome・Safari 26・Firefox 159 で対応(2026-10 に全主要ブラウザがそろった) | 古い端末では動かないだけになるように書く |
| ビュー遷移(View Transitions) | ページの切り替えをなめらかに | 同じページ内: 主要ブラウザ対応(2025-10)。ページをまたぐ: Chrome・Safari(Firefox は未対応) | 複数ページのサイトで、なくても困らない飾りとして |
| アンカー配置(anchor positioning) | 吹き出しをボタンの横にくっつける | Chrome・Firefox 147(2026-01)。Safari は資料で食い違い | 吹き出し・メニュー。今はまだ様子見 |
| `<details>` / `<dialog>` / `popover` | 開閉・窓・ポップオーバーを HTML だけで | 主要ブラウザ対応 | FAQ・写真の拡大・メニュー |
| `::details-content` + `interpolate-size` | details をなめらかに開く | Chrome 系だけ(Firefox 未対応・Safari は試験版) | `@supports` で囲む |
| `:has()` | 「中に○○がある箱」に色を付けるなど | 主要ブラウザ対応 | フォームの入力エラーの枠など |
| コンテナクエリ | 箱の幅に合わせて中身を変える | 主要ブラウザ対応 | カードを置く場所で形を変える |
